## 1. Verdict executiv

### Verdict general

**GO pentru validare executabilă într-un checkout complet.**  
**NO-GO pentru merge, instalare pe server, pilot sau release.**

Branch-ul a trecut prin mai multe iterații de audit și remediere și are acum o
fundație mult mai solidă decât versiunea inițială:

- Child Mode are o singură intrare ghidată;
- audio-ul este bufferizat, limitat și sincronizat;
- inputul este blocat semantic în timpul instrucțiunilor;
- offline readiness este fail-closed și legată de buildul curent;
- pachetul obligatoriu poate fi inspectat și reparat same-origin;
- progresul este protejat înainte de scrierile asincrone;
- IndexedDB, bootstrap-ul, audio-ul și cleanup-ul au timeout sau izolare;
- Preview Mode-ul adultului nu mai modifică mastery, dificultatea sau session lock;
- există garduri și suite dedicate pentru migrare, cache, trasare și toate jocurile.

Aceste afirmații sunt confirmate prin inspecția codului și a contractelor statice.
Nu există însă încă dovada că branch-ul compilează și trece toate testele după
ultima serie de modificări. Această diferență este esențială: auditul nu transformă
codul neexecutat într-un release validat.

## 3. Constatări finale și remedieri aplicate

### FINAL-001 — GitHub Actions consuma minute la fiecare iterație

Severitate: P1 operațional  
Status: remediat

Workflow-ul era declanșat la fiecare actualizare de PR, deși branch-ul are multe
iterații și testarea completă nu trebuie plătită pentru fiecare commit intermediar.
Ultima rulare automată a eșuat înainte să producă pași sau loguri utile; aceasta nu
constituie dovadă că testele codului au eșuat.

Remediere:

- workflow exclusiv `workflow_dispatch`;
- `npm ci`, nu instalare liberă;
- concurrency cu anularea rulării anterioare;
- timeout de 20 minute;
- o singură rulare manuală după închiderea verificărilor locale.

### FINAL-002 — Cache-urile vechi puteau fi amestecate cu buildul curent

Severitate: P0  
Status: remediat static

Un `release.json` putea proveni din cache-ul curent, iar clipurile audio dintr-un
cache Workbox sau repair mai vechi cu același pathname.

Remediere:

- release identity caută toate răspunsurile cache-uite și acceptă numai commitul
  HTML curent;
- asset-urile runtime sunt indexate numai din cache-ul care conține release-ul
  curent și din repair cache-ul versiunii curente;
- repair cache-urile vechi sunt excluse și șterse;
- playback-ul folosește aceeași selecție de cache ca offline gate-ul;
- MP3-urile necesită status bun, corp nenul și content type audio;
- build gate-ul verifică toate clipurile obligatorii în `sw.js`.

### FINAL-003 — Autorepararea putea valida cache-ul fără să îl folosească la redare

Severitate: P0  
Status: remediat static

Poarta offline vedea repair cache-ul, dar playback-ul folosea numai `fetch()`.
În airplane mode, un clip reparat putea fi declarat instalat și totuși să nu fie
redat.

Remediere:

- playback-ul caută mai întâi asset-ul în cache-ul release-ului curent sau în
  repair cache-ul curent;
- numai în lipsa acestuia folosește fetch same-origin cu timeout;
- testul de repair rămâne poartă Chromium.

### FINAL-004 — Operațiile IndexedDB puteau rămâne suspendate

Severitate: P0  
Status: remediat static

Un open blocat sau o tranzacție care nu emite evenimente putea ține finalul
nivelului ori bootstrap-ul în așteptare nelimitată.

Remediere:

- timeout 6 secunde pentru open;
- tratarea explicită `onblocked`;
- timeout 8 secunde pentru write și abort best-effort;
- închiderea unei conexiuni care sosește după timeout;
- timeout 10 secunde pentru bootstrap-ul profilului;
- fallback vizual React în loc de ecran alb;
- snapshot sincron de urgență rămâne sursa de recovery.

### FINAL-005 — Confirmarea unei scrieri vechi putea șterge snapshot-ul nou

Severitate: P0  
Status: remediat static

Snapshot-ul de urgență este acum envelope versionat și are token unic. O scriere
IndexedDB șterge snapshot-ul numai dacă tokenul curent este exact tokenul pe care
l-a confirmat.

### FINAL-006 — Vocea putea rămâne activă după suspendare

Severitate: P1  
Status: remediat static

La background/freeze se opresc acum atât muzica, cât și vocea. Aceasta eliberează
speech gate-ul și evită un container `inert` rămas după revenire.

### FINAL-007 — Preview-ul adultului modifica progresul copilului

Severitate: P0 produs/date  
Status: remediat static

Butonul din Parent Mode folosea o sesiune normală: putea înregistra attempt, ajusta
dificultatea, debloca sesiunea și seta session lock.

Remediere:

- `previewMode` explicit în sesiune;
- `persistProgress: false` în motor;
- fără attempt, mastery, difficulty update, co-play, session record sau lock;
- revenire în Parent Mode după nivel;
- UI explică faptul că preview-ul nu modifică progresul;
- testul principal compară profilul înainte și după preview.

### FINAL-008 — Cleanup-ul unui joc putea opri cleanup-urile următoare

Severitate: P1  
Status: remediat static

Cleanup-urile jocului sunt acum izolate individual. O excepție este raportată
local prin `data-game-cleanup-state`, dar restul resurselor sunt eliberate.

### FINAL-009 — Acoperirea de test scăzuse după refactorizare

Severitate: P0 pentru release  
Status: parțial remediat; rămâne muncă

Suita principală fusese redusă considerabil. Au fost restaurate:

- migrarea v1, v2 și v3;
- testul continuous touch pentru `trace-road`;
- full-catalog smoke pentru toate cele 15 jocuri;
- Preview Mode fără mutații;
- child session real și session lock;
- repair cache;
- recovery după crash;
- pair-joining cleanup;
- Axe, performanță și offline audio de bază.

Rămâne lipsă validarea UI a stage-urilor maxime pentru toate arhetipurile. Smoke-ul
dovedește că fiecare joc ajunge la ready și se curăță, nu că fiecare ladder stage
maxim poate fi completat corect.

### FINAL-010 — Scriptul trace-touch nu mai găsea testul dedicat

Severitate: P1  
Status: remediat

A fost restaurată suita și denumirea exactă căutată de
`npm run test:web:trace-touch`.

### FINAL-011 — Puzzle-ul putea introduce devreme o formă fără clip

Severitate: P1 UX  
Status: remediat pentru nivelurile timpurii

Hexagonul nu are încă un cue real. Nivelurile mici folosesc exclusiv forme cu audio;
hexagonul rămâne disponibil numai când stage-ul maxim cere mai multe forme decât
setul vorbit. Soluția finală este un clip Higgs aprobat.

### FINAL-012 — Build gate-ul nu verifica pachetul audio obligatoriu

Severitate: P0  
Status: remediat static

`check-web-build` verifică acum:

- identitatea commit/tree/lockfile/node;
- shell JS sub 100 KiB gzip;
- toate cele 15 chunk-uri lazy în precache;
- toate cue-urile din pachetele startup în service worker.

## 4. Evaluarea arhitecturii finale

### Frontend shell

Stare: bună, necesită execuție

Puncte forte:

- React deține ecranele și semantică;
- Pixi rămâne renderer, nu sursă de adevăr;
- Home este ghidat și simplu;
- Parent Mode nu importă implementările tuturor jocurilor;
- bootstrap și importurile dinamice au fallback;
- cleanup-ul ecranelor și jocurilor este izolat.

Risc rămas:

- bundle-ul real după noile importuri trebuie măsurat;
- snapshot-urile trebuie inspectate pe ambele motoare;
- layouturile extreme nu au fost văzute în acest mediu.

### Runtime audio

Stare: arhitectural solid, nevalidat pe dispozitiv

Puncte forte:

- AudioBuffer, un singur clip activ;
- timeout fetch/decode/playback;
- cache LRU 48;
- preload concurent 3;
- voice/SFX buses și ducking;
- stable cue IDs pentru golden slice;
- current-release Cache Storage;
- repair same-origin.

Risc rămas:

- memoria reală a 48 de buffer-e;
- comportamentul iOS/WebKit la suspendare;
- loudness, clipping și naturalețea celor 321 de clipuri;
- `audit:speech:strict` nu poate fi încă verde pentru întreg catalogul.

### Offline/PWA

Stare: contract bun, dovadă fizică lipsă

Puncte forte:

- controller și release identity;
- cache current-release;
- pack readiness;
- fail-closed;
- repair;
- update numai la limite sigure.

Risc rămas:

- clean install real;
- update peste versiunea instalată;
- quota mică/cache evicted;
- repair urmat de restart în airplane mode;
- timp și dimensiune totală pentru precache-ul monolitic.

### Backend local/persistență

Stare: bună, cu datorie de simplificare

Puncte forte:

- IndexedDB + fallback;
- migrări;
- sanitizare profundă;
- emergency snapshot generation-safe;
- timeout-uri;
- storage health;
- export/delete.

Datorie:

- `storage.ts` păstrează încă API-ul istoric de scriere, iar
  `durableProfile.ts` este calea nouă. După validare trebuie rămas un singur
  repository de scriere pentru a evita ocolirea accidentală a snapshot-ului.

### Scheduler și progres

Stare: mai bun decât versiunea inițială, încă orientativ

Puncte forte:

- recență;
- suport;
- abandon;
- latență prudentă;
- varietate de domeniu;
- seed unic pe sesiune;
- unlock tolerant.

Risc rămas:

- nu persistă rolul și motivul selecției;
- nu distinge complet dificultatea logică de ajutorul motor;
- Parent Mode nu oferă încă recomandarea următoare și activitatea fără telefon.

### Produs premium

Stare: direcție corectă, execuție vizuală incompletă

Există acum o lume comună și trei jocuri prioritare, dar nivelul premium necesită
încă:

- artă finală și character bible Lumi;
- feedback semantic specific fiecărei mecanici;
- snap/magnetism și motion final;
- audio Higgs aprobat;
- observație reală copil–adult;
- Parent Mode recomandativ.
